# 每日内容维护

每天北京时间 **09:30** 检查 [Awesome AI Motion](https://github.com/guanmo-ai/awesome-ai-motion) 的公开内容。维护任务审读新增作品、作者原文、源码入口及纠错；有有效变化才更新本站并发布。上游没有变化时不制造更新，也不发送重复通知。成功发布、失败或需要处理的问题会通知维护者。

每日维护由 Codex 本地自动化执行，需要维护电脑在线并运行 Codex；GitHub Actions 负责发布通过检查的网站成品。

当前黑色 Aceternity 授权套件保持原样。模板开发源码保留私有，公开仓库只部署 `dist/` 网站成品、作品索引与文档。不要运行 `build:legacy`，该命令会构建历史免费界面；公开 `build` 也不能重建当前付费版本。

## 检查与候选数据

1. 检查公开仓库工作树，保留已有修改；比较上游当前 commit 与 `dist/catalog-meta.json` 的来源版本。仅修改文档或脚本不自动视为作品内容变化。
2. 取得明确 commit 的公开 `data/cases.json`，保存在本地候选目录。审读差异并记录完整 40 位 commit 与文本规范化为 LF 后的 SHA-256。不要以分支地址作为可复现的发布来源。
3. 使用显式版本和校验值导出候选，先不要覆盖已发布 `dist/works.json`：

```bash
node scripts/import-catalog.mjs /path/to/cases.json --commit VERIFIED_COMMIT --sha256 VERIFIED_SHA256 --output /path/to/candidate/works.json
```

候选同目录生成 `catalog-meta.json`，包含上游 commit、源文本校验值、导出文件校验值及实际统计。`--metadata /path/to/catalog-meta.json` 可指定元数据输出位置。版本与校验值必须成对提供；显式版本必须同时指定候选输出。导入校验失败不会写候选文件。

未提供参数时的旧入口仍固定为最初取得的已验证快照，仅用于恢复；每日维护必须使用显式参数。不能把“获得数据”当作“来源已审读”，散列只能证明所用字节与记录一致。

## 核验与发布

审查新增、变更及删除记录，确认作者、原帖、分类、媒体地址与资料归属。作者原文逐字保留，译文和任务描述分开标记；只有来源链接的条目不得带本站正文。不得生成未公开提示词、编造模型归因或补充私有采集记录。来源疑似异常、数据大量减少或结构变化时保留已上线版本并报告问题。

候选导出通过字段完整性、唯一 ID、公开 URL 及提示词边界检查。封面和制作指南固定到本次确认的 commit。发布统计来自实际 `works.json`，不要求固定作品数量。

确认有效更新后，将同一份 `works.json` 和 `catalog-meta.json` 同步至公开成品与私有开发副本，按实际内容更新 README、SOURCE.md 及资料统计。仅内容变更无需重新构建套件；涉及交互或指南链接支持时由私有源码构建压缩成品，付费源码和 source map 不提交。

```bash
node scripts/verify-site-artifact.mjs
```

该门禁验证黑色默认页面、必要成品资源、非空唯一作品记录、元数据校验值和统计一致性，并拒绝 source map。也可传入候选成品目录：`node scripts/verify-site-artifact.mjs /path/to/candidate-site`；该目录必须包含完整网站资源和数据元数据。

本地检查搜索、分类、作者原文复制及新增案例入口，只提交公开成品、数据和必要文档。推送 `main` 后确认 GitHub Pages 部署成功，再核验线上数据与界面。推送成功不等于已发布；部署失败时保留可用版本并报告实际原因。无有效变化不提交空更新，不调整黑色套件布局。

元数据不填虚构的“今日更新”日期。实际来源版本、内容快照与发布提交分别记录；本机路径、账户信息、下载包与采集过程不进入公开仓库。
